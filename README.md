# cargo-dep-graph

Инструмент визуализации графа зависимостей для менеджера пакетов **Cargo**
(язык Rust). Вариант №9.

Готовые средства (сам менеджер пакетов и сторонние библиотеки для получения
зависимостей) не используются: информация о зависимостях запрашивается
напрямую у API crates.io по HTTP средствами стандартной библиотеки Python.

## Общее описание

Приложение получает список зависимостей Cargo-пакета, строит из них граф с
учётом транзитивности, выполняет над графом операции (прямые и обратные
зависимости, порядок загрузки) и формирует визуальное представление графа
в формате PlantUML и в виде изображения SVG.

Работа разбита на пять этапов:

1. **Минимальный прототип с конфигурацией** — настройка через опции
   командной строки.
2. **Сбор данных** — получение прямых зависимостей пакета с crates.io.
3. **Основные операции** — построение графа алгоритмом DFS с рекурсией,
   с учётом максимальной глубины и обработкой циклов.
4. **Дополнительные операции** — вывод обратных зависимостей пакета.
5. **Визуализация** — генерация диаграммы PlantUML и сохранение SVG.

## Параметры (настройки)

Параметры задаются опциями командной строки:

| Опция         | Описание                                         | По умолчанию |
|---------------|--------------------------------------------------|--------------|
| `--package`   | Имя анализируемого пакета                        | обязательный |
| `--source`    | URL репозитория или путь к файлу тестового графа | обязательный |
| `--mode`      | Режим работы: `real` или `test`                  | `real`       |
| `--output`    | Имя файла с изображением графа (SVG)             | `graph.svg`  |
| `--depth`     | Максимальная глубина анализа (1–100)             | `3`          |

Для всех параметров реализована проверка корректности: пустое имя пакета,
недопустимый режим, отсутствующий тестовый файл, нечисловая или выходящая
за диапазон глубина — всё приводит к понятному сообщению об ошибке.

## Описание функций

### `config.py`

- `parse_config` — разбирает аргументы и возвращает объект `Config`.
- `build_parser` — создаёт парсер опций командной строки.
- `Config.as_items` — возвращает параметры парами ключ-значение.

### `sources.py`

- `create_source` — выбирает источник данных по режиму работы.
- `CratesIoSource.direct_dependencies` — прямые зависимости с crates.io.
- `TestRepoSource.direct_dependencies` — прямые зависимости из файла.
- `TestRepoSource.all_packages` — список всех пакетов тестового графа.

### `graph.py`

- `build_graph` — строит граф зависимостей рекурсивным DFS.
- `DependencyGraph.reverse_dependencies` — обратные зависимости пакета.
- `load_order` — порядок загрузки зависимостей (топологический).

### `visualize.py`

- `to_plantuml` — текстовое представление графа на языке PlantUML.
- `to_svg` — отрисовка графа в формате SVG.
- `save_svg` — сохранение SVG в файл.

## Сборка и запуск

Требуется только Python 3.8+ (сторонние библиотеки не нужны).

### Через скрипты запуска

Linux/macOS:

```bash
chmod +x run.sh
./run.sh --package serde --source https://crates.io/api/v1/crates --depth 2
```

Windows:

```bat
run.bat --package serde --source https://crates.io/api/v1/crates --depth 2
```

### Через Makefile

```bash
make run ARGS="--package serde --source https://crates.io/api/v1/crates"
make example-test     # демонстрация на тестовом графе
make example-real     # демонстрация с реальным crates.io
make test             # запуск всех тестов
make clean            # удалить сгенерированные файлы
```

### Запуск тестов

```bash
python3 -m unittest discover -s tests -p "test_*.py" -v
```

### Тестовый режим (без обращения к сети)

```bash

  --package A \
  --source examples/test_repo.txt \
  --mode test \
```

## О сравнении с реальным менеджером пакетов

Порядок загрузки (`load_order`) строится топологической сортировкой: сначала
загружаются листовые зависимости, затем зависящие от них пакеты. Реальный
Cargo дополнительно учитывает feature-флаги, целевые платформы (`target`),
dev- и build-зависимости, а также разрешение версий через `Cargo.lock`.
В этом инструменте учитываются только обычные (`normal`) необязательные
зависимости последней версии пакета, поэтому для пакетов со сложным набором
features возможны расхождения в составе графа — это ожидаемое следствие
упрощённой модели.

## Обработка особых случаев

- **Циклические зависимости.** Обход помечает посещённые пакеты и не входит
  в них повторно, поэтому цикл не приводит к бесконечной рекурсии.
- **Максимальная глубина.** Обход прекращается при достижении заданной
  пользователем глубины.
- **Тестовый режим.** Вместо реального URL можно указать путь к файлу
  описания графа, где пакеты именуются большими латинскими буквами.
